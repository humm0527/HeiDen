本目录包含两个业务模块、快捷入口和离线样例测试。输入需使用匿名列名；特殊证券覆盖默认关闭。

# 01 风险事件与 02 券商评价：业务说明

本项目用于检验券商集中度分类对风险股票的提前识别情况。01根据市场事实识别风险事件；02结合事件发生前的券商分类，计算命中率、预警率、预警天数，以及单公司股票打分模型的风险股票拦截、风险股票分档。

本文说明01、02的业务流程、数据要求、计算口径和结果阅读方式，不涉及配置与运行环境。

## 一、两个模块分别做什么

| 模块 | 主要问题 | 输入 | 输出 |
| --- | --- | --- | --- |
| `01_risk_events` | 哪些股票发生了风险，何时发生？ | 分类文件提供的证券及日期范围，行情、涨跌停价格、ST状态、交易日历和证券生命周期 | 风险事件、连续跌停区段、低门槛压力观察，以及供02使用的配套数据与交接清单 |
| `02_peer_benchmark` | 券商是否在风险发生前识别了这些股票？ | 01风险事件及配套数据，各券商历史集中度分类 | 命中率、预警率、预警天数、事件评价明细；单公司模式另有A—G档位统计和风险股票拦截、风险股票分档 |

全行业与单公司使用同一套风险事件识别逻辑。01中的分类文件用于确定证券和日期范围，分类档位本身不决定是否发生风险事件；02才使用分类档位评价识别效果。

整体流程为：

```text
分类输入 → 确定证券和日期范围 → 01识别风险事件
                                      ↓
历史逐日分类 ───────────────→ 02评价提前识别效果 → 汇总与明细
```

## 二、两种日常业务流程

### 单公司股票打分模型

输入为完整的原始月度截面文件夹，文件名为 `股票打分结果YYYYMMDD.xlsx`，使用 `Sheet1` 中的证券代码、证券名称、集中度分类。已有完整逐日分类时，也可以直接复用。

快捷入口依次完成：逐日分类准备、01风险事件计算、02单公司评价、风险股票拦截与分档生成。普通命中率与风险股票拦截统计截止日所在年份的结果；风险股票分档需要自2025年1月15日起的完整历史。

当前快捷入口使用2026年或之后的截止日。截止日期留空时，有月度截面就取最新截面文件日期；没有月度截面时取已有逐日分类的最后日期。指定日期为非交易日时，向前回溯至最近交易日。

### 全行业券商评价

输入为包含21家券商分类的本季度集中度CSV，并结合历史季度CSV计算。当前季度文件决定计算截止日；以前季度提供年初以来分类及预警回看所需历史。

快捷入口先运行01，再运行02，输出各券商的评价结果。全行业入口不生成单公司股票打分模型专用的风险股票拦截、风险股票分档。单券商文件不能代替21家券商的全行业输入。

## 三、月度截面如何转换为逐日分类

原始月度文件位于 `02_peer_benchmark/data/股票打分结果/`，逐日分类保存在 `02_peer_benchmark/data/single/`，按季度输出 `集中度分类_YYYYQn.csv`。

逐日文件固定为四列：`biz_date`、`stk_code`、`证券名称`、`单公司`。日期按交易日展开，证券代码保留前导零和市场后缀。

转换沿用已确认的规则：

- 首期2025年1月15日至2月28日使用1月15日截面；3月的交易日使用2月28日截面。
- 相邻截面的边界当天仍使用上一份截面，从下一交易日起切换。文件日期为非交易日时，边界向前回溯。
- 缺失月份延续上一份实际存在的截面。例如2026年6月1日至8月3日使用5月29日截面，8月4日至8月31日使用8月3日截面。
- 原始截面的空分类统一填G。转换复制已有分类，不重新计算股票评分。
- 匿名副本默认不启用特定证券的强制档位覆盖；测试使用虚构证券验证覆盖机制，实际业务名单由使用者另行提供。

快捷入口优先检查 `single`。逐日数据完整覆盖2025年1月15日至本次截止日时，跳过转换；为空或缺少交易日时，由完整月度截面重新生成所需数据并保存。格式异常会提示整理，不能将任意非空文件当作可用分类。

选择较早截止日时，只截取本次需要的数据，不截短已有逐日缓存。复用检查不比较原始Excel是否被修订；若修改了已覆盖日期的截面，或换用另一套打分模型，应先移出旧逐日CSV，再重新生成。

## 四、01的风险事件口径

### 非ST连续跌停

以正常交易日的收盘价等于当日跌停价识别跌停事实。主板达到连续3个交易日、创业板和科创板达到连续2个交易日时形成正式风险事件；当前规则排除北交所。

非跌停、停牌或转为ST会中断连续区段。同一证券可以发生多次独立事件。连续跌停区段明细保留长度至少为2的区段，因此区段数不等于正式风险事件数。

“首次事实日期”是该段第一个跌停日；“风险认定日期”是达到板块阈值的日期。02以首次事实日期作为提前识别的评价基准。

### 新增ST

识别从非ST转为ST或*ST的变化。ST转为*ST不重复认定新增事件；观察期开始前已经是ST的股票，不因跨年而新增一次事件。摘帽后再次转为ST可以形成新的事件。

### 日期与数据完整性

普通年度计算从主分类文件所属年份的1月1日开始，到文件最大业务日期结束。补充历史分类可以扩充证券范围和辅助日历，但不会自动将普通年度结果变为跨年度统计。

单公司快捷入口为满足风险股票分档需求，会准备覆盖2025年起的跨年度风险事件，再分别截取年度报告与分档需要的范围。仅有当年风险事件的旧批次，不能直接用于跨年度风险股票分档。

01还输出低门槛压力观察供进一步分析；它与正式风险事件分开，不直接加入02正式风险事件的统计分母。缺少必要行情、ST或生命周期等事实时，应检查数据完整性，不能把缺失数据解释为“没有风险”。

## 五、02如何评价券商分类

### 分类取值时间

每个事件使用首次事实日前一交易日收盘时已经可用的分类。对连续跌停事件，取第一个跌停日前一交易日；对新增ST事件，取首次成为ST日前一交易日。事件当天才出现的分类或ST状态不倒推为提前识别。

各券商按自身原始分类映射为危险或非危险，同名字母不代表相同风险含义。单公司A—E为非危险，F、G为危险；评价截止日已为ST的证券，沿用02的ST危险状态优先规则。无法识别的分类或缺失状态保留异常记录，不能直接解释为已命中。

### 主要指标

| 指标 | 计算含义 |
| --- | --- |
| 事件命中率 | 提前识别的风险事件数 ÷ 风险事件总数。同一股票多次发生事件时逐次评价。 |
| 证券命中率 | 至少有一次风险事件被提前识别的去重证券数 ÷ 发生风险事件的去重证券数。 |
| 观察期预警率 | 观察期内进入该券商危险集合、且之后发生对应风险的去重证券数 ÷ 观察期内进入该券商危险集合的去重证券数。 |
| 预警天数 | 评价截止日仍连续处于危险状态的最近一段分类，从该段起始分类日期到首次风险事实日期的交易日距离。 |

各指标分别展示非ST连续跌停、新增ST及两类风险合计。预警率还提供分类截面维度的结果。分母为零时标记不适用；历史不足以证明连续危险状态起点时，正式预警天数留空。

## 六、风险股票拦截与分档

两张表只输出股票打分模型结果，不计算或回填现行分类的对照结果。

| 项目 | 风险股票拦截 | 风险股票分档 |
| --- | --- | --- |
| 统计区间 | 截止日所在年份的1月1日至截止日 | 2025年1月15日至截止日 |
| 统计维度 | 全部风险、新增ST、非ST连续跌停 | 单公司A—G各档 |
| 主要结果 | 风险事件数、命中事件数、事件命中率、风险股票数、命中股票数、证券命中率 | 区间风险事件数量、日均档位数量、占比 |
| 分类依据 | 首次事实日前一交易日分类及该日ST状态 | 按首次事实日前一交易日的原始模型档位归组 |

风险股票分档的日均档位数量为“该档每天股票数之和 ÷ 区间交易日数”；占比为“该档区间风险事件数量 ÷ 该档日均股票数”。分子按事件计数，包含同一股票的多次事件，因此不能将该占比解释为去重股票的风险发生概率，也不能直接与风险股票拦截的证券命中率比较。

风险股票拦截、风险股票分档不使用预警天数。逐事件评价明细用于核对分类取值日期、模型档位、命中情况和是否计入风险股票拦截。

## 七、结果在哪里、先看哪些文件

快捷入口每次在所选结果保存位置创建独立运行目录，默认位于交接目录的 `结果输出/`。新计算不会自动改写旧批次。

| 文件 | 用途 |
| --- | --- |
| `风险股票清单.csv` | 本次截止年份的风险证券去重名单 |
| `风险事件明细.csv` | 同一年度的逐事件记录，一只股票可以有多条 |
| `券商预警指标最终汇总_YYYYQn.csv` | 集中查看各券商命中率、预警率和预警天数 |
| `券商风险命中率汇总_YYYYQn.csv` | 分风险类型查看事件及证券命中率 |
| `全券商风险事件命中明细_YYYYQn.csv` | 核对每个事件、每家券商的识别情况；单模型模式只包含单公司 |
| `单公司A-G档位风险事件汇总_YYYYQn.csv`、对应明细CSV | 单公司单模型的年度档位风险分布 |
| `风险股票拦截_股票打分.csv`、`风险股票分档_股票打分.csv` | 单公司议题所需两张结果表 |
| `风险股票拦截与分档风险事件评价明细.csv` | 风险股票拦截、风险股票分档的逐事件核对依据 |
| `运行结果.json`、`运行日志.txt` | 确认成功状态、统计截止日及异常原因 |

最终中文CSV位于本次运行目录最外层；输入副本、下载分块、转换记录、交接清单和校验材料位于 `核对材料/`。其中 `风险股票拦截与分档事件输入` 是计算输入目录，最终风险股票拦截、风险股票分档应在上层结果目录查看。

单独运行01时，重点查看风险事件、连续跌停区段和低门槛压力观察三类CSV，以及 `02输入清单_YYYYQn.json`。该清单将事件、日历、ST、证券范围和生命周期等材料关联起来，供02读取。02评价阶段读取已经准备好的文件，不直接访问米筐。

## 八、更新数据与结果核对

分类数据更新到新日期后，市场事实和风险事件也必须覆盖新日期。单公司逐日数据不足时可按月度规则延展；全行业必须提供实际包含新日期分类的CSV，旧全行业结果不会自动补出未来分类。

联网快捷入口会重新获取所需市场事实并计算本次结果，不依赖旧的 `2026Q3_20260831` 风险事件输入目录。独立的市场底座维护用于后续离线复用，与01风险事件计算分别管理；联网快捷入口不自动更新这个底座。

查看结果时先确认本次 `运行结果.json` 为 `SUCCEEDED`，再核对统计起止日、事件数量和分类覆盖。风险股票分档包含跨年度事件，事件总数可能大于当年的 `风险事件明细.csv`。运行失败、目录被移走或清理后，旧日志中的“全部完成”不能证明文件仍然存在。

当前快捷入口暂不计算收益率，后续按另行确认的收益口径处理。

## 九、源码发布与本地路径说明

两个模块的核心代码通常通过脚本自身位置定位文件。以下两项仍与本地市场底座的位置有关，迁移时需要特别核对：

| 位置 | 本地路径依赖 | 迁移时的处理 |
| --- | --- | --- |
| `01_risk_events/src/riskaudit/market_foundation/manual_increment.py` 的市场更新入口 | 默认根据源码位置向上查找原项目的 `data/local_market_connection.json`。只复制01、02时，该默认文件可能不存在。 | 使用市场更新功能时，通过 `--connection` 明确指定新电脑上的连接文件。普通联网快捷计算不要求这个旧项目文件。 |
| 两个模块的 `src/riskaudit/local_market_connection.py` | 本地底座连接中的 `market_lake_root` 必须为绝对路径，且该目录下的 `duckdb/market_catalog.duckdb` 必须存在。 | 使用离线底座时，将连接文件指向本机实际底座目录，并核对配套证据文件路径；不要直接沿用别的电脑的绝对路径。 |

根目录和两个模块各自的 `.gitignore` 用于隔离本地运行材料：本地任务JSON、模块内README和交付说明、真实分类与行情数据、原始Excel、结果目录、运行记录及虚拟环境不提交。月度转换目录中的Python源码与通用说明仍保留在源码仓库。此根目录README作为01、02的统一业务说明提交。

忽略文件不会删除本地文件，也不影响程序按原路径读取它们。下载源码不等于取得完整数据包；业务输入、市场数据和本地任务文件由运行者另外准备。`SHA256SUMS.json` 已按本匿名副本重新生成；`acceptance.py --source-only` 检查源码完整性与模块导入，不要求本地任务文件，也不代表真实业务数据验收。

当前副本统一使用匿名券商编号；单模型标识为 `single`，逐日目录为 `data/single`。本副本不包含原名称对应表，也不包含真实业务数据。
